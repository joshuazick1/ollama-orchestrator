# src/types/

Cross-cutting TypeScript types: API request shapes, error events, and Ollama response types.

## Purpose

Central place for types that span multiple modules. API request types live here so the frontend can mirror them through [src/shared-types.ts](../shared-types.ts) and the auto-generated mirror under [frontend/src/types/generated/](../../frontend/src/types/).

Files of record:

- [api-request.types.ts](api-request.types.ts) — Request bodies for `/api/generate`, `/api/chat`, `/api/embeddings`, plus shared request context types. Audit C-5 origin.
- [error-event.ts](error-event.ts) — `ErrorEvent` shape used by [src/utils/error-classifier.ts](../utils/error-classifier.ts) and [src/storage/error-event-store.ts](../storage/error-event-store.ts). Documented contract lives in [docs/ERROR-EVENT-SCHEMA.md](../../docs/ERROR-EVENT-SCHEMA.md). Also exports the canonical `ErrorType = 'network' | 'server' | 'timeout' | 'unknown'` union — promoted to this file in iter63 Wave 1 so the persisted error-event taxonomy has a single source of truth. Any module that records an `ErrorEvent` must use this `ErrorType`, not a locally redeclared variant.
- [ollama/](ollama/) — Ollama upstream response types: `OllamaGenerateResponse`, `OllamaShowResponse`, `OllamaProcessListResponse`. Re-exported from [ollama/index.ts](ollama/index.ts).

## Ownership

- Owns the public type contract between the backend and the frontend. Changes here are breaking unless the change is purely additive.
- Domain types that are part of the runtime data model (e.g. `AIServer`, `ServerModelMetrics`) live in [src/orchestrator/orchestrator.types.ts](../orchestrator/orchestrator.types.ts). This folder is for request shapes, event shapes, and external (Ollama) response shapes.

## Local Contracts

- The frontend type mirror is generated by [scripts/sync-types.sh](../../scripts/sync-types.sh) from these files. Do not edit the generated mirror by hand.
- `ErrorEvent` is the contract between classification (in [src/utils/](../utils/)) and storage (in [src/storage/](../storage/)). Its shape is documented in [docs/ERROR-EVENT-SCHEMA.md](../../docs/ERROR-EVENT-SCHEMA.md).
- The Ollama response types in [ollama/](ollama/) are a strict subset of the upstream Ollama API. They are not authoritative for the whole Ollama API surface.

## Work Guidance

- New request bodies belong in [api-request.types.ts](api-request.types.ts). Pair them with a Zod schema in [src/middleware/validation.ts](../middleware/validation.ts).
- New error event fields must be added to `ErrorEvent` in [error-event.ts](error-event.ts) and to the schema doc in [docs/ERROR-EVENT-SCHEMA.md](../../docs/ERROR-EVENT-SCHEMA.md).
- New upstream response types (e.g. a new Anthropic response) go in a new subfolder analogous to [ollama/](ollama/).

## Verification

- `npm run validate-types` — Validates the backend↔frontend type mirror.
- `npm run typecheck` — TypeScript must compile cleanly.
- `npm run build` — `prebuild` runs `scripts/sync-types.sh`, which regenerates the frontend mirror from these types.
