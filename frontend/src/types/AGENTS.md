# frontend/src/types/

Frontend type definitions and the auto-generated `generated/` mirror of backend types.

## Purpose

Single place for TypeScript types used by the frontend. The bulk of the types are mirrored from the backend (see [src/shared-types.ts](../../../src/shared-types.ts) and [scripts/sync-types.sh](../../../scripts/sync-types.sh)). Hand-written types cover the frontend's own UI shapes.

Files of record:

- [generated/](generated/) — Auto-generated mirror of backend types. Generated by `prebuild` (see `package.json` at the repo root). Do not edit by hand.
- (Note: a hand-written `types.ts` exists at [frontend/src/types.ts](../types.ts) — re-export aggregator for non-generated types. See [frontend/AGENTS.md](../../AGENTS.md) for the high-level shape.)

## Ownership

- Owns the frontend-side type contract. Hand-written types live at [frontend/src/types.ts](../types.ts) (one level up from this folder); the auto-generated mirror lives in this folder.
- The mirror is regenerated by the build pipeline. Hand-edits are overwritten.

## Local Contracts

- The mirror must be regenerated whenever the backend type shape changes (`npm run build` runs `prebuild` → `scripts/sync-types.sh`).
- `validate-types` (run from the repo root) is the primary check that the mirror is in sync with the backend.

## Work Guidance

- New frontend-only types: add them to [frontend/src/types.ts](../types.ts), not to [generated/](generated/).
- New backend types that should be exposed to the frontend: add them to [src/shared-types.ts](../../../src/shared-types.ts) (or to a file re-exported from there), then regenerate the mirror.

## Verification

- `npm run validate-types` (at the repo root) — verifies the mirror is in sync.
- `npm run typecheck` (in `frontend/`) — must pass.
